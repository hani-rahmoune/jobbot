# jobbot

Discord alerting for internship and apprenticeship openings in France, pulled
directly from employer applicant tracking systems (ATS) — no aggregators, no
recycled listings.

The project's non-negotiables, architecture, and milestone plan live in
[CLAUDE.md](CLAUDE.md); read that first if you're changing anything here.

## Status

- **M0–M5** — done: `Job` model, config loading, the Greenhouse adapter, the
  `filters.yaml` engine, the SQLite state store, the Discord publisher, and
  the orchestrator (`jobbot/run.py`).
- **M6** — done: shared classification/HTML helpers, the Lever, Ashby, and
  generic JSON-LD adapters, a French company list.
- **M7** — done: the discovery CLI (`jobbot/discover.py`) — finds which ATS
  a company's own careers page uses, root-first with up to two hops of
  careers-link following, instead of hand-guessing board tokens.
- **M8** (more ATS adapters: Taleez, Flatchr, Beetween, DigitalRecruiters,
  Talentsoft, Workday) — not built yet.
- **M9** — done: GitHub Actions deployment (see
  [docs/DEPLOY.md](docs/DEPLOY.md)), `--stats` and `--check`.

## Running it

```bash
uv sync                 # install dependencies into .venv
uv run python -m jobbot.run --dry-run   # one cycle, zero Discord requests
uv run python -m jobbot.run --seed      # first-ever run: baseline the board without posting
uv run python -m jobbot.run             # the real thing (needs JOBBOT_DISCORD_WEBHOOK_URL)
uv run python -m jobbot.run --stats     # summarize the state database and exit, fetches nothing
uv run python -m jobbot.run --check     # validate config/env/state without fetching or posting
```

`--help` lists every flag (`--config-dir`, `--filters`, `--settings`,
`--verbose`). Exit codes: `0` success, `1` every configured source failed
this cycle, `2` a config/environment problem (e.g. the webhook URL is
missing and `--dry-run` wasn't passed, or `--check` found something wrong).

Deploying it to run unattended is a separate, one-time set of steps — see
[docs/DEPLOY.md](docs/DEPLOY.md) for the exact order (repo, webhook, secret,
seed, then turn on the schedule).

## Finding companies to poll

Hand-typing ATS board tokens doesn't scale and misses most small companies
(see `discovery/seeds/README.md` for the story). Instead:

```bash
uv run python -m jobbot.discover --input discovery/seeds/example.txt --delay 2.0
```

reads a list of company websites (never job boards — see CLAUDE.md rule 3)
and writes what it finds to `discovered.yaml`: for each company, whichever
ATS its careers page uses and the board identifier, `tier: cold`, `enabled:
true`. Anything it couldn't resolve goes to `unresolved.txt` instead, with
the full path it walked trying.

**`discovered.yaml` is never auto-promoted.** It's a draft for you to read,
not curated config — review it, then promote what looks right by moving (or
copying) its entries into a file under `companies/` and changing `tier` from
`cold` to `warm` or `hot` (whatever polling frequency you actually want;
`cold` on its own is never picked up preferentially). `load_companies()`
already merges every `*.yaml` file in `companies/`, so a new file there needs
no other wiring. `discovered.yaml` and `unresolved.txt` are both
git-ignored — they're regenerated by `jobbot.discover`, not meant to be
committed themselves.

## Quickstart (development)

```bash
uv sync                 # install dependencies into .venv
uv run pytest -v        # run the test suite (offline, no network calls)
uv run ruff check .     # lint
```

Coverage isn't collected by default locally (it costs ~30% of runtime, and the
suite has a five-second budget). CI always runs with it; to check coverage
yourself:

```bash
uv run pytest --cov=jobbot --cov-report=term-missing
```

## Configuration

Nothing you'd want to change lives in code:

- `companies/*.yaml` — which employers to poll, and on which ATS. See the
  comment block at the top of `companies/hot.yaml` for how to find a
  Greenhouse board token from a careers page URL.
- `settings.yaml` — runtime knobs (poll interval, User-Agent contact, etc.).
  Any key can be overridden with a `JOBBOT_`-prefixed environment variable.
- `filters.yaml` — location and keyword preferences. Edit this to relocate
  or change what you're searching for; `jobbot/` itself contains no
  hardcoded city, keyword, or search term (enforced by
  `test_no_hardcoded_search_terms`).

Secrets never live in yaml — they come from the environment only (a `.env`
file works too; it's git-ignored):

- `JOBBOT_DISCORD_WEBHOOK_URL` — **required** to actually publish. The
  webhook URL for the Discord channel jobs get posted to.
- `JOBBOT_DISCORD_ERROR_WEBHOOK_URL` — **optional**. A separate webhook for
  operational error messages (e.g. a source repeatedly failing), so failures
  don't get lost in the same channel as job postings. Falls back to not
  reporting errors to Discord at all if unset.

Nothing in `jobbot/` reads either of these directly (`jobbot/publisher.py`
takes a webhook URL as a plain argument) — wiring them from the environment
into a running bot is the orchestrator's (M5) job.
